## 배경

‘두근두근 카드 뒤집기’는 2026 경북게임개발사관학교 교육 과정에서 ChatGPT Codex와 함께 만든 웹 미니게임입니다. 난이도별 **실시간 순위표**가 있는데, 게임은 로그인 없이 바로 시작합니다.

로그인이 없는 게임의 순위표는 조작하기 가장 쉬운 곳입니다. 브라우저 개발자 도구만 열면 점수를 보내는 요청을 직접 만들 수 있기 때문입니다.

## 위협 정리

막고 싶었던 것은 세 가지였습니다.

1. **말이 안 되는 점수**: 50라운드에서 나올 수 없는 점수나, 0초 만에 끝난 기록
2. **도배**: 짧은 시간에 기록을 계속 보내 순위표를 채우는 것
3. **남의 기록 수정·삭제**

## 1. 익명 인증으로 “누가 보냈는지” 남기기

Firebase **익명 인증**은 사용자가 아무것도 입력하지 않아도 브라우저마다 고유한 `uid`를 줍니다. 이것만으로도 규칙에서 `request.auth.uid`를 쓸 수 있어,

- 인증되지 않은 요청은 거절하고
- 기록에 작성자 `uid`를 남겨 **본인 기록만** 다룰 수 있게 합니다.

## 2. 서버 규칙으로 기록의 일관성 검사

게임 규칙상 가능한 범위를 서버 규칙에 옮겨 적었습니다. 난이도별 제한 시간, 라운드 수와 점수의 관계, 시간 보너스의 최댓값처럼 **게임 설계에서 계산되는 상한**을 넘는 기록은 저장되지 않습니다.

```js
// 개념 예시: 실제 필드와 값은 게임 저장소의 규칙을 따릅니다.
allow create: if request.auth != null &&
  request.resource.data.uid == request.auth.uid &&
  request.resource.data.score is int &&
  request.resource.data.score >= 0 &&
  request.resource.data.score <= maxScore(request.resource.data.difficulty) &&
  request.resource.data.createdAt == request.time;
```

## 3. 제출 간격 제한

같은 사용자가 짧은 간격으로 연달아 제출하지 못하도록, 서버 규칙에서 **제출 간격**을 검사해 너무 짧으면 거절했습니다.

여기에 클라이언트 쪽 보완도 했습니다.

- 기록은 **먼저 로컬에 보관**하고, 연결이 돌아오면 동기화합니다.
- 같은 기록이 두 번 올라가지 않도록 **중복 제출을 막습니다.**

## 막지 못하는 것도 적어 두기

무료(Spark) 요금제에서는 서버 함수(Cloud Functions)를 쓸 수 없어, 서버가 게임을 다시 재생해 보는 **플레이 검증**은 하지 않았습니다. 그래서 **정상 범위 안에서 꾸며낸 기록**은 규칙만으로는 가려낼 수 없습니다.

이 한계는 숨기지 않고 포트폴리오와 이 글에 적었습니다. 보안에서 “다 막았다”고 말하는 것보다 **어디까지 막았는지**를 정확히 말하는 것이 더 중요하다고 생각합니다.

## 배운 점

- 로그인이 없어도 **익명 인증**으로 규칙에서 쓸 수 있는 신원을 만들 수 있습니다.
- 게임 설계에서 나오는 **상한값**은 그대로 서버 규칙의 검증 조건이 됩니다.
- 무료 요금제의 한계 안에서 막을 수 있는 것과 없는 것을 구분하고, **못 막는 것은 명시**합니다.
