## 왜 지도 SDK를 쓰지 않았나

‘한국 랜덤여행’은 다트를 던져 여행지를 정하는 앱입니다. 필요한 것은 길 찾기나 위성 사진이 아니라 **시·군·구 경계선이 그려진 한 장의 지도**와, 다트가 **어느 시군구에 떨어졌는지** 판정하는 기능이었습니다. 지도 SDK는 무겁고 API 키와 요금이 필요해, 통계청 행정경계 GeoJSON(시도 17 · 시군구 250)을 직접 그리기로 했습니다.

## 1. 좌표 투영: 위경도 → 화면

위도·경도는 구 위의 각도라 그대로 그리면 한반도가 옆으로 퍼져 보입니다. 한국 정도 범위에서는 간단한 투영으로 충분했습니다.

```text
x = 경도 × cos(중간 위도)
y = −위도
```

경도에 `cos(중간 위도)`를 곱해 가로 비율을 보정하고, 화면은 아래로 갈수록 y가 커지므로 위도에 `−`를 붙입니다.

성능을 위해 GeoJSON 폴리곤은 **앱 시작 때 한 번만** 이 “월드 좌표”의 `Path`로 바꿔 둡니다. 화면 크기에 맞추는 확대·이동은 `Path`를 다시 만들지 않고 캔버스 변환(`MapFit`)으로 처리합니다.

## 2. 그리기 분리: 움직이는 것과 안 움직이는 것

다트가 날아가는 동안 매 프레임 지도 250개 폴리곤을 다시 그리면 버벅입니다.

- 정적인 지도: `RepaintBoundary` 안의 `KoreaMapPainter`
- 움직이는 다트: 별도의 `DartOverlayPainter`

이렇게 나누면 다트 애니메이션 중에 지도는 다시 그려지지 않습니다. 다트는 `idle → charging → flying → landed` 상태 머신을 가진 컨트롤러 하나가 관리합니다.

## 3. 착지 판정: Ray casting

다트가 떨어진 점이 어느 시군구 안에 있는지는 **점-폴리곤 판정**으로 알아냅니다. 점에서 한쪽으로 반직선을 그었을 때 폴리곤 경계와 **홀수 번** 만나면 안, 짝수 번이면 밖입니다.

```dart
bool contains(List<Offset> ring, Offset p) {
  var inside = false;
  for (var i = 0, j = ring.length - 1; i < ring.length; j = i++) {
    final a = ring[i], b = ring[j];
    final crosses = (a.dy > p.dy) != (b.dy > p.dy) &&
        p.dx < (b.dx - a.dx) * (p.dy - a.dy) / (b.dy - a.dy) + a.dx;
    if (crosses) inside = !inside;
  }
  return inside;
}
```

구멍이 있는 폴리곤은 같은 방식(even-odd 규칙)을 모든 고리에 적용하면 구멍 안쪽이 자연스럽게 “밖”이 됩니다. 이것으로 육지(어느 시군구) · 북한 · 바다를 구분합니다.

> 위 코드는 원리를 보여주기 위해 단순화한 버전입니다.

## 4. 문제: 다트가 자꾸 바다에 빠진다

처음에는 화면의 무작위 좌표로 다트를 날리고, 떨어진 곳을 판정했습니다. 그런데 지도 면적의 상당 부분이 바다와 북한이라, **갈 수 없는 곳이 너무 자주** 뽑혔습니다. 다시 던지게 하면 “랜덤으로 정해준다”는 앱의 취지가 흐려집니다.

### 해결: 결과를 먼저 뽑고, 다트를 거기로

순서를 뒤집었습니다.

1. 250개 시군구 중 하나를 먼저 고릅니다.
2. 그 시군구의 경계 상자 안에서 점을 뽑고, 실제 폴리곤 안에 들어오는 점만 씁니다. (계속 실패하면 중심점)
3. 그 점의 화면 좌표를 향해 다트를 발사합니다.

사용자에게는 여전히 다트가 날아가 꽂히는 것처럼 보이지만, 결과는 항상 실제 시군구입니다. 시드를 고정한 **200회 랜덤 테스트**로 모든 결과가 육지이고, 돌려받은 점이 그 시군구 안에 있는지 확인했습니다.

## 배운 점

- 지도 SDK 없이도 **좌표 투영, 점-폴리곤 판정, 렌더링 분리**만으로 충분한 지도를 만들 수 있었습니다.
- 랜덤을 “공정하게” 보여주는 것과 결과를 “쓸모 있게” 만드는 것은 다른 문제입니다. 결과를 먼저 정하고 연출을 맞추는 방법이 둘 다 잡았습니다.
- 랜덤이 들어간 로직은 **시드를 고정한 테스트**로 검증할 수 있습니다.
