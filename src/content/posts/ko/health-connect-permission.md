## 문제 상황

‘루티니’는 삼성 헬스·애플 건강의 걸음 수, 운동 거리, 체중을 불러와 루틴을 기록합니다. Play 스토어 비공개 테스트 빌드에서 이상한 일이 생겼습니다. 사용자가 권한 화면에서 **모두 허용**을 눌렀는데도 앱은 이렇게 표시했습니다.

> 접근 권한이 거부되었습니다.

## 원인 1: 내가 요청하지 않은 권한

`health` 플러그인의 소스를 직접 읽어 봤습니다. 운동 기록(`WORKOUT`) 타입을 요청하면 플러그인이 **내부적으로 두 권한을 함께 요청**하고 있었습니다.

- `READ_DISTANCE`
- `READ_TOTAL_CALORIES_BURNED`

그런데 매니페스트에는 칼로리 권한이 없었습니다. Health Connect는 매니페스트에 선언되지 않은 권한이 하나라도 섞이면 **요청 전체를 거부**합니다. 사용자가 무엇을 누르든 결과는 “거부”였던 것입니다.

```xml
<uses-permission android:name="android.permission.health.READ_TOTAL_CALORIES_BURNED" />
```

## 원인 2: iOS 전용 데이터 타입

`DISTANCE_WALKING_RUNNING`, `DISTANCE_SWIMMING`은 **iOS(HealthKit) 전용** 타입이었습니다. Android에서 조회하면 예외가 났습니다. 플랫폼별로 데이터 타입 목록을 분리했습니다.

- iOS: `DISTANCE_WALKING_RUNNING`, `DISTANCE_SWIMMING`
- Android: `DISTANCE_DELTA`, 수영 운동 세션의 거리

화면에는 두 플랫폼의 데이터를 같은 형태로 합쳐 보여줍니다.

## 함께 다듬은 것

- 권한이 이미 있으면 팝업 없이 바로 진행합니다.
- Health Connect가 없거나 업데이트가 필요하면 설치 화면으로 안내합니다.
- 자동 동기화(앱 실행, 복귀, 15분마다)는 **silent 모드**로 동작해 권한 팝업을 반복해 띄우지 않습니다.
- Play Console의 **건강 앱 권한 신고**를 새 권한에 맞게 고쳐, 권한별 사용 목적을 실제 기능과 일치시켰습니다.

## iOS 실기기에서만 HealthKit이 안 되던 문제

시뮬레이터에서는 되는데 iPhone 실기기에서는 HealthKit이 동작하지 않았습니다. `Runner.entitlements` 파일은 있었지만 Xcode 타겟의 `CODE_SIGN_ENTITLEMENTS`에 **연결되어 있지 않아**, 서명된 앱에 HealthKit 권한이 빠져 있었습니다. Debug·Release·Profile 설정에 모두 연결하고, 서명된 앱에 `com.apple.developer.healthkit`이 들어 있는 것을 확인했습니다.

## 덤: 저장소 공개 전 보안 점검

저장소를 공개하기 전에 점검하다가 더 큰 문제를 찾았습니다. 로그인 전 “아이디 찾기”를 위해 `account_lookup` 컬렉션을 `allow read: if true`로 열어 두었던 것입니다. Firestore 규칙은 “이름과 생년월일이 맞을 때만 조회”를 강제할 수 없어서, **공개된 웹 API 키만으로 전체 회원의 아이디·이메일·이름·생년월일을 읽을 수 있는** 구조였습니다.

무료 요금제라 서버 함수로 가려진 아이디만 돌려주는 방법은 쓸 수 없었고, 이름·생년월일은 추측하기 쉬워 해시로 바꿔도 완전한 보호가 되지 않았습니다. 그래서:

- 규칙을 **본인만 읽고 쓰게** 잠갔습니다.
- 아이디 찾기 기능을 없애고 **비밀번호 재설정 메일**만 남겼습니다.
- 새 버전은 로그인할 때 예전에 저장된 본인 인덱스 문서를 지웁니다.
- 로그인하지 않은 요청이 **403으로 거부되는 것**을 직접 확인했습니다.

## 배운 점

- 권한 문제가 이해되지 않으면 **플러그인 소스**까지 내려가 봐야 합니다. 내가 요청한 것과 실제로 요청되는 것이 다를 수 있습니다.
- 권한은 “실제로 쓰는 것만, 읽기 전용으로” 선언하되, 플러그인이 함께 요구하는 권한까지 **매니페스트 · 스토어 신고 · 개인정보처리방침**에 일관되게 반영해야 합니다.
- `allow read: if true`는 편의 기능 하나 때문에 **전체 회원 정보**를 여는 문이 될 수 있습니다. 기능을 빼는 것이 가장 안전한 해결일 때도 있습니다.
